# AI across a project

Consider the request: let customers reschedule a booking. The table describes possible assistance, not a completed system or a guarantee that a tool succeeds.

| Stage | A useful AI contribution | What the team still needs to decide or verify |
| --- | --- | --- |
| Requirements | Suggest missing questions and acceptance examples | Allowed change window, availability, permissions and payment implications |
| Existing code and design | Locate relevant code and compare approaches | Actual dependencies, established project patterns and tradeoffs |
| Implementation | Draft connected screen, API and data changes | Correct behavior across boundaries and appropriate scope |
| Verification | Suggest tests, help write checks and investigate failures | Whether the checks cover the intended behavior, security and regressions |
| Delivery and maintenance | Assist with configuration review, release notes and log investigation | Release readiness and effects in the running system |

Which stage takes most of your time? Choose a concrete task within that stage when exploring tools. AI assistance does not require adding an AI feature to the application itself.
