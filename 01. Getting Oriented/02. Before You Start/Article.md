# Before You Start

Welcome to AI-Assisted Development: A Practical Introduction. You will follow a short ChatGPT investigation, a small code fix with Claude Code, and a command-line feature that you can run yourself.

## What you need

- Experience writing code and working with an existing software project, plus basic Git familiarity.
- Git, Python 3 and your preferred code editor.
- Claude Code CLI with paid access, such as Claude Pro, for the subscription-based repository demonstrations.
- ChatGPT Free and GitHub Free are sufficient for their parts. Advanced Python and prior AI or machine-learning knowledge are not required.

The Python example uses only the standard library. Follow the [official Claude Code quickstart](https://code.claude.com/docs/en/quickstart) for installation, sign-in and current platform requirements. Usage limits depend on your account.

## Get your student resources

Open the [course resource repository](https://github.com/Harsha-Global/AI-Assisted-Development). Its numbered section and lecture folders contain the reference notes, copyable prompts, commands and source code. On GitHub choose Code, then Download ZIP, or use Git to clone it. A complete student ZIP is also attached to this article.

Keep the downloaded materials as a reference copy. In the Download and Set Up the Project article, you will copy the appropriate starting source to a separate practice folder. That avoids mixing your edits with completed examples.

The videos use the demonstration repository recorded for the course. Use the current Harsha-Global resource repository above for your own practice.

## How to follow the demonstrations

Read the request and expected behavior before asking the assistant to edit. Copy the prompt from the matching lecture folder, examine the actual reply and files, then run the checks yourself. AI replies can differ from the recording; compare the behavior and scope, rather than expecting identical wording.

The Starter intentionally contains the whitespace issue. One supplied check fails before the fix; all seven should pass afterward. Do not change a check simply to make a result pass.

## Your first reflection

Think of one familiar task: clarifying a requirement, explaining a function, fixing a bug or checking a change. Write down the intended result and one way to verify it. Keep that task in mind as you watch the next lectures.

This free Udemy course does not include a completion certificate, Q&A or instructor direct messaging. The setup notes, troubleshooting article and self-check resources are provided to help you practise independently.
